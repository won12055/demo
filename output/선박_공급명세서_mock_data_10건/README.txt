선박 물품 공급명세서 mock data 10건

기존 예시 1건을 제외한 추가 가상 명세서 10건입니다.
각 문서에 16개 품목, 전체 160개 품목 행을 포함합니다.
기존 예시의 품목과 추가 품목을 섞고 거래별 수량·단가·선박·공급일을 달리했습니다.
회사, 주소, 담당자, 선박 및 거래 내역은 모두 가상이며 연락처는 example.com을 사용합니다.

파일 구성
documents/: 사람이 읽을 수 있는 공급명세서 텍스트 10개 (UTF-8).
ship_supply_mock_10.json: 문서별 기본 정보와 품목, 합계를 담은 정답 데이터.
ship_supply_mock_items_160.csv: 문서번호를 포함한 품목 단위 데이터 (UTF-8 BOM).

금액과 날짜
금액은 전부 KRW 정수, 단가와 품목 금액은 부가세 별도입니다.
품목 금액 = 수량 × 단가. 공급가액 = 품목 금액 합계.
부가세 = 공급가액 × 10% (원 미만 버림). 합계금액 = 공급가액 + 부가세.
날짜는 YYYY-MM-DD입니다. 문서번호 + 번호가 품목 행의 고유키입니다.
CSV에는 품목 행만 있습니다. 문서별 합계는 JSON에 한 번씩 기록해 중복 합산을 피합니다.

프로젝트 활용
텍스트 명세서를 파서나 정보 추출 모델의 입력으로 쓰고 JSON/CSV를 정답으로 비교합니다.
이 자료 자체는 이미지가 아니므로 OCR의 문자 인식 성능을 측정하려면 먼저 이미지로 만들어야 합니다.
기존 ship_supply_ocr.py는 이미지/PDF의 고정 표 위치를 읽으며 이 TXT/JSON을 직접 입력받지 않습니다.
모델 성능 평가 시 같은 문서의 품목이 학습·평가 데이터에 섞이지 않도록 문서 단위로 나누세요.
